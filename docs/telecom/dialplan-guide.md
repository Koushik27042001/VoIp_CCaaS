# Dialplan Guide

The Asterisk dialplan decides where calls go.

## `[from-internal]`

Used by browser agent extensions.

Current internal extension route:

```ini
exten => _1XXX,1,NoOp(Internal browser SIP call to ${EXTEN})
 same => n,Dial(PJSIP/${EXTEN},30)
 same => n,Hangup()
```

Meaning:

- Agents can dial extensions like `1001`, `1002`, `1010`.
- Asterisk routes the call to the matching PJSIP endpoint.

## Outbound PSTN Prefix

Current generated outbound pattern:

```ini
exten => _9X.,1,NoOp(Outbound PSTN call through configured trunk)
 same => n,Dial(PJSIP/${EXTEN:1}@${OUTBOUND_TRUNK},60)
 same => n,Hangup()
```

Meaning:

- Agent dials `9` plus a phone number.
- Dialplan strips the first digit with `${EXTEN:1}`.
- Call routes through `${OUTBOUND_TRUNK}`.

Production requirement:

- Define `OUTBOUND_TRUNK` in your Asterisk globals or replace it with a real trunk endpoint.

## `[from-trunk]`

Used by inbound SIP provider calls.

Current generated inbound route:

```ini
exten => _X.,1,NoOp(Inbound trunk call for ${EXTEN})
 same => n,Dial(PJSIP/1001,30)
 same => n,Hangup()
```

Meaning:

- Any inbound DID currently routes to extension `1001`.

Production requirement:

- Replace this with DID mapping, queues, IVR, business hours, or failover routing.

- Confirm Asterisk uses the `_1XXX` route.
